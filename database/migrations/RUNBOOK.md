# Production migration runbook

1. Retained execution requires separate approval. Stop writes; record row counts and business totals.
2. Take and verify a full `FastGuyDB` backup. Copy it off-host. Test restore to another database.
3. Restore the verified backup to a fresh disposable database. Apply every migration in order through `063_activity_log.sql`, running each matching validator, including `057_validate.sql`, `058_validate.sql`, `059_validate.sql`, `060_validate.sql`, and `061_validate.sql`. After validation, rerun migration 058 with `058_validate.sql`, migration 059 with `059_validate.sql`, migration 060 with `060_validate.sql`, and migration 061 with `061_validate.sql` to prove idempotency. Do not treat disposable validation as separate retained approval.

4. After disposable validation and separate retained approval, run `000_preflight_history.sql`, `010_expand_schema.sql`, `020_backfill_legacy.sql`, `030_constraints_indexes.sql`, `035_backend_hardening.sql`, `039_inventory_waste_state.sql`, `040_production_hardening.sql`, `040_validate.sql`, `041_delivery_failure_recovery.sql`, `041_validate.sql`, `042_login_bruteforce_lock.sql`, `043_inventory_adjustment_audit.sql`, `044_manual_refund_audit.sql`, `045_notification_read_receipt.sql`, `046_cod_shift_settlement.sql`, `046_cod_shift_settlement_validate.sql`, `047_low_stock_threshold.sql`, `047_validate.sql`, `048_homepage_merchandising.sql`, `048_validate.sql`, `049_category_images.sql`, `049_validate.sql`, `050_product_scoped_reviews.sql`, `050_validate.sql`, `052_ingredient_inventory_phase_1.sql`, `052_validate.sql`, `053_inventory_costing_stock_count.sql`, `053_validate.sql`, `054_repair_inventory_text_encoding.sql`, `054_validate.sql`, `055_verify_inventory_text_repair.sql`, `055_validate.sql`, `056_verify_inventory_text_repair_balances.sql`, then `056_validate.sql`, `057_order_item_cost_snapshot.sql`, `057_validate.sql`, `058_staff_shift_ownership.sql`, `058_validate.sql`, `059_shift_schedule_order_timeout.sql`, `059_validate.sql`, `060_operating_finance.sql`, `060_validate.sql`, `061_work_shift_attendance_approval.sql`, `061_validate.sql`, `062_staff_pay_rate_snapshot.sql`, `062_validate.sql`, `063_activity_log.sql`, and `063_validate.sql` in order using an account with DDL rights. Rerun each numbered migration once after its validator to verify its migration-history idempotency guard. Never run `init.sql` against retained data. Do not run retired `database/20260802_backend_hardening.sql`.
5. `041_local_demo_seed.sql` is optional and local-development only. Never run it in production. Opt in per connection with `EXEC sys.sp_set_session_context @key=N'FASTGUY_ALLOW_DEMO_SEED', @value=1;`, then run seed and rerun `040_validate.sql`.
5. Treat any thrown error as a stop. Correct source data or script assumptions; rerun from `000_preflight_history.sql`.
6. Manually inspect unknown roles, duplicate email/SKU/default variants/idempotency keys, product/variant mismatches, malformed modifier CSV/JSON, coupon ownership/order links, order totals/status history, and application reads/writes.
7. Keep `Role`, `FavoriteProduct`, `CartItemModifier`, `OrderItemModifier`, `ClaimedCoupon`, `CouponUsage`, legacy columns, and `DeliveryZone`. Archive/remove only in a separately approved migration after cutover.
8. Smoke-test login, favorites, cart modifiers, checkout, coupons, order history, inventory, payment, staff and shipper workflows.
9. For enforcement-only rollback run `rollback/030_relax_constraints.sql`. For complete rollback, stop writes and restore the verified backup; the migration intentionally has no destructive reverse backfill.

Assumptions: database name is `FastGuyDB`; SQL Server 2016+; source resembles `eb4d216`; `FavoriteProduct` has `user_id`, `product_id`, `created_at`; `OrderItemModifier` has `order_item_modifier_id`, `modifier_option_id`, `group_name`, `option_name`, `price`; optional `ClaimedCoupon` and `CouponUsage` tables follow the legacy schema when present. Dynamic branches run only when their legacy objects exist.

All `sqlcmd -i` executions for repository SQL files must include `-f 65001`; repository SQL is UTF-8 and may contain Vietnamese text.

`staff_role_snapshot` is assigned by the application from `Users.role_name`; database principals with direct write access to `WorkShift` can supply a misleading valid snapshot, so restrict direct table writes to trusted migration and application accounts.
